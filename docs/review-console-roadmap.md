# 检视裁定台功能优先级

本文描述人工确认 PR/MR 检视意见是否接受的完整预期能力。裁定台不读取、缓存或展示源码、代码片段
及 diff；需要核对代码时跳转到 GitHub/GitLab。界面遵循“一块面板专注一个任务”：意见审核、变更
历史、数据统计和角色管理是互相独立的顶层工作区。

标记含义：`已实现` 表示当前版本已有完整主路径，`部分实现` 表示已有基础但仍需扩展，`待实现`
表示路线图能力。

## P0：正确、安全、可投入使用

P0 是生产使用的准入条件。缺少其中任何一项，都可能造成越权、错误裁定、状态歧义或审计缺口。

| 功能 | 状态 | 验收标准 |
| --- | --- | --- |
| 独立前后端与数据库 | 已实现 | 浏览器不连接主库；操作台和主应用通过版本化 API 对接 |
| 用户登录与会话安全 | 已实现 | 密码哈希；HttpOnly、SameSite 会话；停用用户立即失效 |
| 仓库级权限 | 已实现 | 按 provider + project_path 授予只读或修改权限；默认无权限 |
| 管理员与用户管理 | 已实现 | 创建、启停用户，设置管理员，增删改仓库授权 |
| PR/MR 列表与详情范围 | 已实现 | 选择仓库和具体 PR/MR，读取其全部批次中的全部意见 |
| 大结果集完整读取 | 已实现 | 自动分页读取全部 PR/MR 和意见，不以第一页冒充完整结果 |
| PR/MR 人工检视完成状态 | 已实现 | 权威返回 processing、pending、completed、no_issues、failed |
| 零问题 PR/MR | 已实现 | 没有意见的已完成检视仍可查询，并明确显示 no_issues |
| 意见接受/拒绝 | 已实现 | 修改权限用户可裁定；只读用户不能写入 |
| 拒绝理由 | 已实现 | 拒绝必须选择标准原因分类并填写详细理由；“其他”同样必须说明 |
| 需要补充信息 | 已实现 | 审核者可暂缓裁定并写明待补事实，PR/MR 继续保持待裁定 |
| 裁定语义拆分 | 已实现 | 人工 `decision_status` 与自动 `verification_status` 独立存储和展示 |
| 单任务工作区 | 已实现 | 审核页不展示历史；历史页完全只读；角色页只管理访问权限 |
| 独立变更历史工作区 | 已实现 | 按仓库、PR/MR、意见选择，仅展示状态时间线，无裁定入口 |
| 追加式审计 | 已实现 | 记录前后状态、前后理由、操作者快照、来源和 UTC 时间 |
| 并发写保护 | 已实现 | 使用 expected_updated_at；过期写入返回 409，不覆盖他人决定 |
| 幂等状态写入 | 已实现 | 相同状态和理由重复提交不产生虚假审计事件 |
| 服务间身份 | 已实现 | 使用独立服务令牌；浏览器不持有主应用令牌 |
| 基础筛选和搜索 | 已实现 | 可按意见状态筛选，按标题、描述和文件路径搜索 |
| 判断所需元数据 | 已实现 | 显示描述、等级、分类、路径、行号、PR 链接、检视/合并 SHA、自动验证和批次时间 |
| 明确错误与空状态 | 已实现 | 无权限、并发冲突、零问题、无历史和服务不可用均给出具体反馈 |
| 禁止源码展示 | 已实现 | API 和前端均不返回或渲染代码片段；仅提供代码平台链接 |

P0 已全部实现，并由接口权限、状态校验、并发冲突、旧库迁移和完整检视状态回归测试覆盖。

## 已交付的数据统计页

统计页是独立顶层工作区，只做只读分析，不混入意见裁定或历史操作。它支持精确到时间的起止范围，
并按用户可访问的仓库范围统计：当前被接受的有效意见数、用户最终确认贡献、确认误报数，以及误报
数量最多的五个仓库。重复修改同一意见不会重复累计贡献；统计始终以该意见的当前最终裁定及最终
裁定人快照为准。

## P1：团队协作和日常效率

P1 不改变裁定事实的正确性，重点解决多人审核、大量意见和跨平台协作效率。

| 功能 | 验收标准 |
| --- | --- |
| 审核任务分配 | PR/MR 或单条意见可指定审核人 |
| 主动认领 | 审核者可认领未分配任务，并避免重复劳动 |
| 个人工作队列 | 提供待我审核、我已审核、无人认领、即将超时视图 |
| 批量裁定 | 多选接受/拒绝；批量拒绝仍要求原因，并逐条写审计 |
| 重复意见关联 | 可将意见标记为另一条意见的重复项，并保留主从关系 |
| 仓库审核策略 | 配置严重级别阻塞规则、必填依据、允许角色和完成时限 |
| MR 合入结论 | 将“人工裁定完成”与“可合入/需修改/阻塞/风险放行”分开计算 |
| 处理和修复跟踪 | 成立意见支持未处理、处理中、已修复、风险接受、不处理 |
| 修复验证 | 支持待验证、通过、失败、不需要验证，并记录验证人和依据 |
| commit 过期提示 | 检视 SHA 与当前 SHA 不同时提示意见可能过期，但不展示 diff |
| GitHub/GitLab 状态同步 | MR 合并或关闭后自动转只读；同步最新链接和 SHA |
| 审核摘要回写 | 经确认后向代码平台回写汇总结论，发送前预览，失败可安全重试 |
| 通知 | 分配、补充信息、并发变更、超时和审核完成时通知相关人员 |
| 快捷操作 | 上一条/下一条、键盘裁定、未保存保护、理由草稿 |
| 保存筛选视图 | 保存常用仓库、状态、等级、审核人组合 |
| 审计导出 | 按仓库和时间导出 CSV/JSON，包含完整操作者与原因 |
| 基础运营统计 | 待审数量、平均裁定时长、拒绝原因分布、仓库积压情况 |

P1 页面仍保持任务隔离：分配在“审核队列”，逐条判断在“意见审核”，修复确认在“修复验证”，
只读追溯在“变更历史”，策略配置在“仓库策略”。

## P2：企业治理与规模化

P2 面向多组织、高合规和大规模使用场景。

| 功能 | 验收标准 |
| --- | --- |
| 企业身份源 | 支持 OIDC/SAML 登录，并可从 LDAP/SCIM 同步用户和组 |
| 组与高级 RBAC | 仓库组、组织、标签范围授权，以及自定义角色权限集合 |
| 双人审核 | 高风险仓库支持一审、二审及职责分离，同一人不能完成两级审核 |
| 风险放行审批 | 高危问题的风险接受需要指定角色和二次确认 |
| 不可篡改审计存储 | 审计写入外部 WORM/日志平台，支持保留期限和完整性校验 |
| 安全审计事件 | 记录登录、失败登录、权限变更、导出、认领和外部回写 |
| 实时协作 | Webhook/SSE 推送状态更新和他人正在操作提示 |
| SLA 与升级机制 | 超时自动升级、转派，并按组织日历计算工作时间 |
| 高级分析 | 按仓库、团队、规则、严重度分析趋势和裁定一致性 |
| 规则质量反馈 | 基于拒绝分类评估误报率，为检视规则或模型提供反馈数据 |
| 多实例与灾备 | 操作台横向扩展、数据库高可用、恢复演练和灾备指标 |
| 数据生命周期 | 按组织配置保留、归档、匿名化和合规删除策略 |
| API 与事件订阅 | 对外提供细粒度 API、Webhook 事件和服务账号权限 |

## 明确不进入路线图

- 源代码片段展示。
- PR/MR diff 预览。
- 源码仓库克隆或缓存。
- 在裁定台中编辑代码。
- 将审核操作和历史追溯放在同一面板。

这些能力会增加源码权限、数据泄露和界面复杂度，但不是“确认检视意见是否接受”的必要条件。
